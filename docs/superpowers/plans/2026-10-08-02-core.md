# Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `@rogeriodocarmo/offline-detector-core`, the framework-free detection engine
(state, probe, backoff, platform adapter seam) that the react, web and native packages consume.

**Architecture:** A pure TypeScript state machine, `createOfflineDetector(options)`. Everything
environmental is injected: the platform adapter (interface up/down, foreground), `fetch`, `now`,
`setTimeout`/`clearTimeout`. Core never references `window`, `navigator`, the DOM or React Native.
The interface signal is fast; the probe confirms real reachability. Results are applied under an
"epoch" counter so a result that was overtaken by an interface event or `stop()` is discarded.

**Tech Stack:** TypeScript (strict), Jest, fast-check. No runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-07-offline-detector-design.md` (sections 1, 3, 4, 6)

## Global Constraints

- `OfflineState` is exactly the spec section 3 type: `status` (`online`, `offline`, `unknown`),
  `reason` (`no-interface`, `no-internet`, `null`), `checking: boolean`, `lastChecked` and
  `lastOnlineAt` (`number | null`).
- `unknown` only until the first check completes. `isOnline` is `true` while `unknown`.
- Offline means no real internet: interface up but carrying no data is offline (`no-internet`).
- Backoff while offline: 1000 ms doubling, capped at 30000 ms. Online re-probe every `intervalMs`
  (default 30000). Default probe URLs: `https://cp.cloudflare.com/generate_204`,
  `https://www.gstatic.com/generate_204`.
- Callbacks fire on real status transitions only.
- No runtime dependencies; no custom native code; TypeScript strict; Node per `.nvmrc`.
- Privacy: the only network traffic is the probe request.

## Decisions the spec leaves open

- First result (unknown to known): `onChange` fires. `onOffline` fires if the first result is
  offline (the user needs to know). `onOnline` does NOT fire when the first result is online
  (nothing was lost, so no "Back online").
- `offline(no-interface)` to `offline(no-internet)` is not a status transition: subscribers are
  notified, callbacks are not.
- Config is nested: `createOfflineDetector({ adapter, probe: { urls, timeoutMs, ... } })`.
- A probe URL succeeds when `fetch` resolves with `ok` true or `type === 'opaque'` (what
  `no-cors` yields). Web wraps `fetch` to add `mode: 'no-cors'`.
- A throwing `isInterfaceUp()` is treated as "up" so the probe decides.
- Listener/callback exceptions are caught and passed to optional `onError`, so one bad consumer
  cannot wedge the state machine.

## Review Focus

- Interface drops while a probe is in flight: the late probe result must not resurrect `online`.
  Pinned in Task 4.
- `stop()` while a probe is in flight: no state change after stop, no timer, `checking` cleared.
  Pinned in Task 5.
- `start()`/`stop()` cycles: no duplicated adapter subscriptions, at most one timer. Task 5.
- Empty `urls` or missing `fetch` in probe mode: fail loudly at creation. Task 3.
- `isInterfaceUp()` rejecting: treated as up. Task 4.

### Task 3: Probe

**Interfaces:** Produces `probeAny(urls, deps): Promise<boolean>` where `deps` holds `fetch`,

success, treats rejection, `ok: false` and timeout as failure, clears every timer it set.

- [ ] Tests: first URL ok means one call; first fails and second ok means two calls in order;

- [ ] Commit `feat(core): add sequential reachability probe`.

**Interfaces:** Produces `createOfflineDetector(options): OfflineDetector` with `getState`,
`subscribe`, `checkNow` (start/stop in Task 5). Creation throws on empty `urls` or missing fetch
in probe mode.

- [ ] Tests (each watched failing): initial state is unknown/not checking; interface down gives

      first-result rules above, online-offline-online each fire once, a repeated result fires
