# QA Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the quality-assurance infrastructure from `morse_app` and the website repo
(SonarCloud, Stryker, Playwright + axe, CI wiring) into the monorepo, and fold in the Foundation
review follow-ups.

**Architecture:** All configuration lives at the repo root. Every config file is covered by a
meta-test in `tests/` that is changed first (red) and then satisfied (green). The Playwright base
tests a tiny self-contained static page, so it needs no app yet; library UI tests come later.

**Tech Stack:** Stryker (jest runner), Playwright, `@axe-core/playwright`, SonarCloud scanner
action, GitHub Actions, Jest meta-tests with `yaml`.

**Spec:** `docs/superpowers/specs/2026-10-07-offline-detector-design.md`, section 7.

## Global Constraints

- Prettier: semi, single quotes, trailing commas, width 90. Markdown prose wraps at 100.
- Git Flow; never rebase; commits end with the Co-Authored-By line.
- No `@swc/*`. Jest uses babel-jest. No download-on-run tools (`npx serve@latest` and friends).
- Mutation scope: `packages/core/src` and `packages/react/src`; demos are excluded from coverage
  and mutation scope. Thresholds 80 / 60 / 60.
- Sonar: non-blocking, skipped for Dependabot, forks and an empty `SONAR_TOKEN`.
- E2E: chromium on PRs; 5-project matrix on `main`/`develop` pushes and nightly 02:00 UTC.
- Only the owner creates the SonarCloud project and the `SONAR_TOKEN` secret.

## Review Focus

- A PR that only edits a test file must still mutate the matching source (map test to source).
- A PR touching no mutated source must skip Stryker and still report green.
- `goOffline()` must make `navigator.onLine` false AND fire the `offline` event, or apps never see it.
- The CI step order is asserted exactly; a stray `run` step breaks the meta-test.
- A mobile project must not pull a browser the matrix leg did not install.

## File Structure

- `sonar-project.properties`: Sonar scan scope and exclusions.
- `stryker.config.json`: mutation scope and thresholds.
- `playwright.config.ts`, `e2e/fixtures/{test,stability}.ts`, `e2e/fixtures/serve.mjs`,
  `e2e/fixtures/site/index.html`, `e2e/smoke.spec.ts`: the Playwright base.
- `tsconfig.json` (root): type-checks `tests/` and `e2e/`.
- `.github/workflows/ci.yml` (modified), `.github/workflows/e2e.yml` (new),
  `.github/dependabot.yml` (modified).
- `docs/qa.md`, `docs/OWNER-ACTIONS.md`: documentation.

## Tests

New tests, per level:

- **Unit / meta (Jest, `tests/qa-config.test.ts`, new):** asserts `sonar-project.properties` keys;
  `stryker.config.json` (runner, coverageAnalysis, mutate globs, thresholds, concurrency, ignore);
  `playwright.config.ts` text (five project names, env baseURL, CI-conditional retries);
  `e2e.yml` (triggers incl. cron `0 2 * * *`, PR job chromium only, matrix of five, browser per
  project); root `tsconfig.json` includes; `package.json` scripts; OWNER-ACTIONS Sonar section.
- **E2E (Playwright, `e2e/smoke.spec.ts`, new):** goOffline flips the status text to offline and
  `navigator.onLine` to false; goOnline reverses it; axe finds no violations in both states.
- **Property:** none; there is no pure logic in this change.
- **Mutation:** none new; this change adds no source in the mutated scope. The Stryker config is
  validated by a scoped run on `packages/core/src/index.ts`.

Existing test files disturbed:

- `tests/ci-config.test.ts`: the ordered `run` list of the verify job gains `pnpm typecheck:tests`
  (after `pnpm typecheck`); an `env` assertion for `TURBO_TELEMETRY_DISABLED`; the Dependabot
  ignore list gains `@react-native-community/netinfo`, `@types/react`, `@types/react-native`; a
  mutation-job and Sonar-step assertion. Edited first, watched failing, then the workflow changes.
- `tests/tooling.test.ts`: the inert `.markdownlintignore` assertion is replaced by an assertion on
  the negated globs in the `lint:md` script (and `.markdownlintignore` is deleted, because
  markdownlint-cli2 does not read it).
- `tests/workspace.test.ts` and `tests/packages.test.ts`: read for coupling to the root manifest;
  expected unaffected, verified by running the suite.
- Jest `testMatch` already limits to `tests/**/*.test.ts` and `packages/*/src`, so `e2e/*.spec.ts`
  is not picked up by Jest; Playwright `testDir` is `./e2e` with `testMatch: **/*.spec.ts`.
