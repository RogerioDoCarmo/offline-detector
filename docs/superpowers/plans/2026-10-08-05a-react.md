# React Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `@rogeriodocarmo/offline-detector-react`: the provider, hooks, dismissal state,
i18n helpers and the shared UI types that the web and native packages build on.

**Architecture:** One `OfflineDetectorProvider` creates one core detector per mount, starts it in
an effect and stops it on cleanup. Reads go through `useSyncExternalStore` with a server
snapshot. One internal (unexported) context carries the detector, the platform adapter and the
"checking feedback" registry. Everything else is a pure function (`resolveDismissible`,
`resolveLocale`, `resolveStrings`, `offlineMessage`, `indicatorName`) or a hook over that context.

**Tech Stack:** TypeScript (strict), React 18+ (peer), Jest + jsdom, Testing Library, fast-check.

**Spec:** `docs/superpowers/specs/2026-10-08-ui-layer-contract.md` sections 1, 2 and 5;
`docs/design/strings.md`; `docs/design/components.md` (render props, dismissal, checking feedback).

## Global Constraints

- No DOM and no React Native imports in `src`. Nothing runs before mount; SSR never touches
  `window` or `navigator`.
- `STRINGS` equals `docs/design/strings.md` literally.
- Callback props are read through a ref: changing them never restarts the detector.
- `useRecheckOnReturn` is the only place that re-checks on return; core's `recheckOnForeground`
  stays off.

## Decisions the contract leaves open

- `adapter`, `probe`, `fetch` and `detector` are read **once per mount** (one detector per mount).
  Callbacks, by contrast, are always the latest.
- `detector` (test seam) is not given the callback props: callbacks are wired when the provider
  creates the detector itself.
- `initialStatus` is the first render's assumption on the server and on the client until the first
  check completes (so hydration matches and the UI does not flip to "unknown").
- `useCheckingFeedback()` reports `'brief'` while a **return-triggered** check started by a hook
  with `checkingFeedback: 'brief'` is in flight (`docs/design/components.md`: scheduled probes show
  nothing). It is not a static "any hook is mounted" flag.
- `PieceRenderProps<Theme = unknown>`: the theme type belongs to native, so it is a type parameter.
- A dismissal is keyed to the status it was made in; any change of `status` empties it. A change of
  `reason` alone is not a transition.

## Tests

New files (all literal expected values):

- `src/strings.test.ts`: the full table per locale, `resolveLocale` cases, `resolveStrings`
  overrides, `offlineMessage` (both modes, all reasons), `indicatorName`.
- `src/strings.property.test.ts` (fast-check): `resolveLocale` never throws and returns one of the
  three locales for any string; `resolveStrings` override precedence and no-mutation of `STRINGS`.
- `src/dismissal.test.ts` and `src/dismissal.property.test.ts`: `resolveDismissible` truth table
  over all option combinations (property: against an independent model); `useDismissals` behavior
  and "reset on every status transition and only then" (property over random event sequences).
- `src/provider.test.tsx`: lifecycle (one start, stop on unmount, StrictMode double mount leaves
  one live detector, no leaked timers or listeners), SSR with `renderToString`, callbacks fire on
  transitions only, changing callbacks does not restart, `useNetworkStatus`, `useOfflineDetector`,
  `initialStatus`, missing provider error.
- `src/recheck.test.tsx`: subscribe only while mounted, one shared probe for several hooks,
  `onResult`, latest boolean, `checkingFeedback` aggregation in `useCheckingFeedback`.

Existing tests disturbed: `src/index.test.ts` keeps the `packageName` assertion and gains an
export-surface assertion (the exact list of runtime exports). `tests/packages.test.ts` needs the
`packageName` export only; it is untouched. `jest.config.cjs` switches to `jsdom`; SSR tests
declare `@jest-environment node` per file so "touches no window" is real.

Mutation: `pnpm mutation --tempDirName stryker-tmp` scoped to `packages/react/src`; the score is
reported as measured.
