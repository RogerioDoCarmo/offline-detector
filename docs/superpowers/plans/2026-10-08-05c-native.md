# Native UI Layer Implementation Plan (Plan 5c, phase 1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the phase 1 half of `@rogeriodocarmo/offline-detector-native`: the native platform
adapter, the swipe-dismiss hook, the theme, and the four props-driven presentational pieces
(`Snackbar`, `Banner`, `Indicator`, `FullScreen`).

**Architecture:** Everything is props-driven. Pieces receive state-derived props, strings,
callbacks and light overrides (`icons`, `style`, `testID`). They never import runtime code from
`@rogeriodocarmo/offline-detector-react` (it lands in parallel); the structural types they need
live in `src/contract-types.ts` and are swapped for imports in phase 2. Animation uses the
built-in `Animated` API with the native driver only (opacity and transform). Gestures use
`PanResponder`. No Reanimated, no gesture-handler, no `react-native-web`, no native code.

**Spec:** `docs/superpowers/specs/2026-10-08-ui-layer-contract.md` (sections 1, 4, 5) and
`docs/design/` (tokens, components, accessibility, strings).

## Tests

Policy: literal expected values, never values computed by the code under test. Coverage of
`packages/native` at 95 percent lines and branches or better. Mutation testing is not required for
UI packages.

### New unit tests

- `theme.test.ts`: every token of `lightTheme` and `darkTheme` against the literal tables in
  `docs/design/tokens.md`; `createTheme` overrides; `useOfflineTheme` with `auto` resolved through
  a mocked `useColorScheme` (light, dark, null), and with forced schemes.
- `hooks.test.tsx`: `useReducedMotion` for `reduced`, `full`, `auto` (initial value from
  `AccessibilityInfo.isReduceMotionEnabled`, change event, unsubscribe on unmount);
  `usePieceTransition` enter and exit timings (durations 200 and 150, reduced 120, native driver).
- `adapter.test.ts`: fake NetInfo and AppState. `isConnected` true, false and null mapping;
  `subscribeInterface` forwards and unsubscribes; foreground fires only on `background` to
  `active` and `inactive` to `active`, never on `active` to `inactive`, never twice in a row;
  unsubscribe removes the AppState subscription; missing NetInfo degrades to always up, with a
  single development warning across several adapters; default lazy loading through `jest.doMock`.
- `use-swipe-dismiss.test.tsx`: `PanResponder.create` is spied so the handlers are driven with
  hand-made gesture states at the exact boundaries: 29 percent vs 30 percent of the width,
  0.49 vs 0.5 px/ms, 7 vs 8 px axis lock, a vertical drag ignored, opposite-direction fling, width
  not yet measured, disabled, terminate springs back, reduced motion has no slide.
- `snackbar.test.tsx`, `banner.test.tsx`, `indicator.test.tsx`, `full-screen.test.tsx`: roles,
  labels only on accessible elements, `accessibilityLiveRegion="polite"` (never assertive), the
  `dismiss` accessibility action plus `dismissHint`, 44 point hit areas, checking state
  (`busy` and `disabled`, label becomes "Checking…"), recovery state, start/end styles for RTL,
  safe-area insets in the position, iOS announcement through `announceForAccessibility`, no
  announcement on Android, full-screen focus handling (`setAccessibilityFocus`, hardware back,
  `onRestoreFocus`).

### Existing tests disturbed

- `src/index.test.ts` keeps asserting `packageName`; it gains assertions that the public API names
  are exported. No other existing test changes. The shared `jest.base.js` is not touched: the
  native package overrides `transform`, `transformIgnorePatterns`, `setupFiles`, `testEnvironment`,
  `haste`, `moduleNameMapper` and `resolver` in its own `jest.config.cjs`.

### Property, E2E, mutation

- Property: none. The logic is a handful of threshold comparisons covered by boundary tests.
- E2E: none for this package in phase 1. There is no device or simulator here, and
  `react-native-web` is forbidden. Device behaviour is verified by the Plan 6 demo app.
- Mutation: not required for UI packages; not run.
