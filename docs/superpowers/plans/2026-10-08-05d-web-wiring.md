# Plan 5d: web wiring (phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development. Write the
> test, watch it fail, then implement.

**Goal:** Add the public `OfflineDetector` component to `packages/web`: provider, tokens, children
and the four pieces, driven by the real `@rogeriodocarmo/offline-detector-react` hooks.

**Architecture:** `OfflineDetector` creates the web adapter and probe fetch once, renders
`OfflineDetectorProvider`, then an inner `Pieces` component (it needs the provider's context) that
reads `useNetworkStatus`, `useDismissals` and `useCheckingFeedback` and decides which pieces show.
Local copies of the shared types are replaced by imports from the react package.

**Spec:** `docs/superpowers/specs/2026-10-08-ui-layer-contract.md`, `docs/design/components.md`,
`docs/design/accessibility.md`.

## Behavior table

| Concern       | Rule                                                                                             |
| ------------- | ------------------------------------------------------------------------------------------------ |
| Launch online | nothing; "Back online" only after a real offline to online transition, for `recoveryMs` (4000)   |
| Offline       | snackbar (Retry), banner, indicator; message "No internet" unless `distinguishReason`            |
| Recovery      | snackbar "Back online" and indicator "online"; banner gone; timer pauses on snackbar interaction |
| Full-screen   | opt-in, only offline and not continued; suppresses banner, indicator and offline snackbar        |
| Retry         | `checkNow()`; pressed Retry shows checking immediately (`checkingDelayMs` 0)                     |
| Background    | checking shows only when `useCheckingFeedback()` is `brief`                                      |
| Dismiss       | `actions.dismiss` iff `resolveDismissible`; calls `dismiss(piece)` then `onDismiss(piece)`       |
| Slots         | replace the piece, receive `PieceRenderProps`; tokens still rendered                             |
| Announcer     | snackbar owns the live region; banner announces only when the snackbar is not visible            |
| `colorScheme` | wrapper with `data-od-theme` only when not `auto`                                                |

## Tests

Unit/integration (`src/offline-detector.test.tsx`, jsdom, REAL react package, fake adapter, fake
fetch; literal expected strings):

- launch online shows nothing, and no "Back online" at launch
- offline shows snackbar, banner, indicator with "No internet"
- reason variants with `distinguishReason`
- dismiss one piece, the others stay; all return after the next transition
- recovery snackbar for exactly `recoveryMs` (fake timers); pauses while hovered
- launch offline shows the pieces
- `fullScreen` opt-in, Continue offline, reset on the next transition
- slots receive `PieceRenderProps`; tokens still present
- pt-BR and es strings; `strings` override
- callbacks fire once per transition (`onOffline`, `onOnline`, `onChange`, `onDismiss`)
- Retry shows checking immediately; `useRecheckOnReturn({ checkingFeedback: 'brief' })` in a child
  shows Checking on a foreground return; without it, nothing
- non-dismissible config hides the dismiss actions
- `colorScheme` wrapper only when not `auto`
- StrictMode leaves one detector (one set of listeners, one probe)
- SSR (`renderToString`, node environment, no `window`) and `hydrateRoot` without a mismatch

Existing tests disturbed: `src/index.test.ts` (export list), `test-utils/index.tsx` and
`src/indicator.tsx`, `src/piece-types.ts` (type imports only). No state leaks: the new tests use
a fresh fake adapter per test.

Property: none (no pure logic beyond a state machine covered by the table above).

E2E (`e2e/web-ui.spec.ts`, fixture `e2e/web-ui-fixture/fixture.jsx`): the existing scenarios now run
against the real `<OfflineDetector>` with a fake `fetch` (the probe), plus a "Retry while the
network is down stays offline" case and recovery.

Mutation: Stryker is scoped to `packages/react/src` in this repo; nothing to add for `web`, and a
scoped run is attempted only if it works unmodified (reported honestly).
