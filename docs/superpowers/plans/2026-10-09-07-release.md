# Release setup (Plan 7, part 2)

**Goal:** a release that cannot publish the wrong thing, needs the owner's approval, and carries
npm provenance, in the owner's existing shape (an annotated tag's message is the release notes).

**Spec:** section 8 of `docs/superpowers/specs/2026-10-07-offline-detector-design.md`.

## Design

```text
owner: git tag -a v0.1.0 -m "<release notes>" && git push origin v0.1.0     (on main)
  release.yml
    verify    read-only   annotated tag? on main? tag == every package version? build + all gates
                          + pack check (tarball contents)
    publish   needs verify, environment npm-publish (owner approves), id-token: write
                          changeset publish --no-git-tag   (OIDC trusted publishing, provenance)
    release   needs publish, contents: write      GitHub Release, body = the tag message
```

- Versions: the four packages are one **fixed** Changesets group, so they always share a version.
- The first publish of each package is manual (npm configures trusted publishers per existing
  package), with provenance off; `docs/RELEASING.md` is the procedure.
- Every third-party action in `release.yml` is pinned by commit SHA.
- `scripts/check-release-tag.cjs` and `scripts/verify-pack.cjs` hold the logic as pure, tested
  functions; the workflow only calls them.
- Each package ships its own `LICENSE` (identical to the root one), so the tarball carries the
  license text.
